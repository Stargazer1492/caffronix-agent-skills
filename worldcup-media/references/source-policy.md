# 来源政策

## 来源分层

一级来源：

- FIFA、赛事组委会、球队官网、国家队官网、俱乐部官网。
- 官方发布会、官方伤情通报、官方赛程、官方技术报告。
- 赛事数据提供方的可核验页面。

二级来源：

- 可信新闻机构、体育媒体、记者署名报道、采访全文。
- 有明确发布时间、作者、编辑责任和原始采访引用的报道。

三级来源：

- 聚合站、搬运号、短视频切片、论坛帖、球迷账号、未署名社媒爆料。
- 这类来源只能提示线索，不能单独支撑关键事实。

## 事实分级

`confirmed`：官方或当事方确认，或多个可信来源一致报道且无相互矛盾。

`reported`：可信媒体报道，但官方尚未确认。公开文案使用“据报道”“多家媒体称”等表达。

`social`：来自X、论坛、球迷社区或视频评论区，只能说明讨论热度和争议方向。

`inferred`：基于公开数据和时间线做出的分析判断。必须说明推理依据，不能写成事实。

`unknown`：来源不足、时间不明、作者不明、图片来源页缺失或内容不可核验。

## 时间规则

- 同时记录`publishedAt`和`eventDate`。旧报道被重新传播时，以事件日期解释背景，以发布日期解释传播状态。
- 用户询问“今天”“最新”“刚刚”时，先核对当前日期和时区，再查最新来源。
- 比赛、伤病、转会、禁赛、首发和阵容信息高度易变，发布前必须二次核对。

## 图片规则

- 人物真实照片优先来自官方图库、新闻图片页、授权图库或可追溯来源页。
- 只保存图片URL不足以公开使用，必须保存图片所在页面URL和版权说明线索。
- 自动抽取的`og:image`、`twitter:image`和结构化数据图片可以进入内部预览视频，但公开发布前仍需核对原文页版权说明。
- 不使用图像生成工具生成现役球员、教练、裁判、名人或新闻现场的伪真实照片。
- 无法确认来源或授权的图片可进入内部`materials.json`，但`usageRisk`必须标为`high`。

## 视频规则

- 视频片段必须记录平台、来源页、发布时间、原作者和可用范围。
- 比赛转播画面通常存在版权限制。公开视频分镜可以描述画面需求，但成片前需要替换为可授权素材、官方可嵌入素材或自制可视化。
- 网页转视频流程可以用于FIFA页面、球队页面、数据页和专题页，但需要保留原始URL。

## 引用要求

每条素材至少包含：

```json
{
  "id": "src_001",
  "title": "",
  "url": "",
  "sourceName": "",
  "publishedAt": "",
  "eventDate": "",
  "sourceType": "official|news|image|video|social|data|other",
  "factLevel": "confirmed|reported|social|inferred|unknown",
  "people": [],
  "teams": [],
  "matches": [],
  "tags": [],
  "summary": "",
  "imageUrl": "",
  "imagePageUrl": "",
  "usageRisk": "low|medium|high"
}
```

## 自动搜索输出

`scripts/search_materials.mjs`生成的素材属于初筛结果。进入成片前必须再经过`normalize_sources.mjs`和人工或Agent复核。

自动搜索结果的限制：

- 搜索页摘要可能缺少完整上下文，关键事实需要打开原文核对。
- 搜索脚本会抽取原文页图片URL。视频工程生成脚本可以下载这些图片进入内部预览成片；公开发布前必须复核图片授权或替换为可授权素材。
- 官方来源和可信媒体优先进入`materials.raw.json`，社媒讨论只作为讨论信号。
