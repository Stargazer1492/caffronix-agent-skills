# 材料准备

## 简历原则

简历修改先处理结构和证据：

- 一页优先，除非研究型岗位、论文较多或用户明确需要长简历。
- 每段经历写清背景、动作、技术或方法、结果。结果可以是指标、规模、用户、性能、效率、上线状态或评审反馈。
- 项目描述要服务目标岗位。无关细节删掉，和JD强相关的能力前置。
- 技术词要能追问。不会解释实现细节的技术名不要堆在技能栏。
- 成绩、排名、奖项和证书只保留能增强岗位匹配的内容。

## 项目经历

项目经历按这条线整理：

```text
问题背景 -> 我的职责 -> 关键方案 -> 技术细节 -> 结果证据 -> 可复盘收获
```

常见问题：

- 只写功能清单，缺少个人贡献。
- 只写技术栈，缺少为什么这样选。
- 只写“提升效率”，没有基线、范围和结果。
- 把团队项目写得像个人独立完成，容易被追问击穿。
- 使用AI工具完成项目时，要说明自己负责的问题定义、验证、集成和迭代，不把工具输出当个人能力证明。

## 岗位适配

针对不同方向调整材料重心：

- 技术岗：突出工程质量、复杂度、性能、稳定性、问题定位和代码能力。
- 算法岗：突出数据、模型、指标、实验设计、误差分析和复现实验。
- 产品岗：突出用户问题、需求判断、数据验证、方案权衡、协作推进和结果。
- 运营岗：突出目标、策略、内容或活动机制、数据复盘和增长结果。
- 设计岗：突出问题定义、信息架构、交互逻辑、视觉系统、验证方式和作品集质量。

## 输出格式

简历反馈建议按优先级输出：

```text
高优先级修改
- 问题
- 原因
- 修改示例

中优先级修改
- 问题
- 原因
- 修改示例

可选优化
- 问题
- 原因
- 修改示例
```

不要只给评价，要给可替换的句子或结构。
